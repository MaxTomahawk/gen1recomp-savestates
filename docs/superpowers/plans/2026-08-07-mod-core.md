# Save States Mod Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the public-API-only, data-only snapshot/index/storage core that every quick, automatic, permanent, and recovery state flow uses.

**Architecture:** `main.lua` is the composition root. It loads mod-local files through the upstream-supported `mod:read` plus `load` pattern; pure files return tables or dependency-injected factories and never import `src.*`. The engine checkpoint remains opaque while the mod owns snapshot metadata, compatibility, migration, indexing, retention, deduplication, and cross-key transaction ordering.

**Tech Stack:** LuaJIT 2.1, Gen1Recomp Mod API 2, `mod.storage`, `mod.checkpoints`, current `modkit.py`, the repository's literal assertion harness.

## Global Constraints

- The distributable mod may not `require("src.*")` or access private engine state.
- Snapshot and index records contain only strings, finite numbers, booleans, and recursively data-only tables with string/positive-integer keys.
- Snapshot format starts at `1`; engine checkpoint format is opaque and separately versioned.
- Different game versions or playthrough ids are hard load rejections.
- Unknown future snapshot formats are hard rejections; supported old formats migrate only through explicit registered steps.
- Index publication occurs only after a payload write succeeds; index removal occurs before payload deletion.
- Corrupt/missing payloads stay recoverable and never crash list/load flows.
- Every behavior change follows observed RED, minimal GREEN, focused suite, `make check`, then a coherent commit.
